# LAN Drop · 局域网闪传

电脑浏览器与手机浏览器打开**同一个地址**，同局域网内自动互相发现，选文件 → 选接收方 → 发送，带实时百分比进度。

**核心特点：入口固定 + 按网络自动分组。** 在任何一个局域网打开同一个网址，同出口（同局域网）的设备自动互见，其他网络的人看不到你 —— 不需要记 IP，也不会串台。

---

## 快速开始

```bash
npm install        # 首次运行，安装 2 个依赖（ws、qrcode）
npm start          # 默认 8000 端口
# 或指定端口：node server.js 9000
```

启动后终端会打印三种入口地址：

```
本机访问 : http://127.0.0.1:8000
局域网   : http://192.168.x.x:8000
主机名   : http://landrop.local:8000   (iOS/macOS 可直接收藏)
```

## 手机怎么连（三种方式，都不用记 IP）

| 方式 | 适用 | 操作 |
|---|---|---|
| **扫码**（推荐，最通用） | 所有手机 | 电脑打开页面 → 点右上角「📷 扫码」→ 手机相机/扫码 App 扫一下，直接打开 |
| **固定主机名** | iPhone/iPad、Mac、Linux | 手机浏览器输入 `http://landrop.local:8000`（**收藏后就固定了**） |
| **局域网地址** | 所有设备 | 电脑页面顶部会直接显示当前地址，照着输一次即可 |

> 只有电脑需要一直开着这个服务；手机只是打开一个网页，不用装任何东西。
> 两台设备必须在**同一个 Wi-Fi** 下（访客网络/AP 隔离见下方「FAQ」）。

## 使用流程

1. **① 选择文件** — 点击区域选择要发送的文件（可多选）
2. **② 选择接收设备** — 已发现的设备以 💻 / 📱 卡片显示，点一下选中（高亮 + "已选"）
3. **③ 发送并看进度** — 点「发送」，进度卡片显示：总进度条、单文件进度、百分比、速度、剩余时间

收到的文件会自动下载到各自设备的下载目录。

## 工作原理

```
   ┌──────── 电脑浏览器 ────────┐        ┌──────── 手机浏览器 ────────┐
   │                            │        │                            │
   │   ① 选文件  ② 选设备 ③ 发送 │        │      自动接收并下载         │
   └──────────┬─────────────────┘        └───────────┬────────────────┘
              │                                      │
              │  信令(发现/握手) ──→ 本机 Node 服务 ←──│
              │                                      │
              └──────── WebRTC 点对点直传（不经服务器）──┘
                              ↕ 直连不通时
                    自动降级：文件经服务器中转
```

- **设备发现**：浏览器通过同源 WebSocket 注册到 Node 服务，服务广播同房间设备列表（15 秒心跳，掉线自动移除）
- **服务器端网络分组**：房间由**服务器按连接的真实来源 IP** 自动计算，客户端无需探测 ——
  - 公网 IPv4 → 按出口 IP 分组（`net-x.x.x.x`）：同一宽带/同一公司出口 = 同一房间
  - IPv6 → 按 `/64` 前缀分组
  - 内网直连 → 按 `/24` 网段分组（本地部署时同一子网互见）
  - 反向代理部署时读取 `X-Forwarded-For` 取真实客户端 IP
  - 优先级：URL `?room=xxx` 显式覆盖 > 服务器自动分组
- **文件传输**：默认走 **WebRTC DataChannel 点对点直传**，60 KB 分块，接收方每 256 KB 回一个 ACK 驱动真实进度，`bufferedAmount > 8 MB` 自动背压暂停
- **自动降级**：若 8 秒内点对点连不上（路由器 AP 隔离、跨网段等），**自动切换为服务器中转**，界面显示黄色「经服务器中转」徽标 —— 保证任何网络环境下都能传成功
- **固定入口**：本地使用时 mDNS 广播 `landrop.local` + `/api/qr` 二维码；公网部署时部署地址本身就是固定入口

## 部署到公网（推荐：真正的"任意网络固定入口"）

把本服务部署到任意能跑 Node 的公网主机（云服务器 / Railway / Render / Fly.io 等），即可获得一个**任何网络都能打开的固定网址**——家里、公司、手机流量，打开的都是同一个入口，服务器自动让**同出口的设备互见**：

```bash
# 云服务器上
npm install
PORT=80 node server.js          # 自动监听 0.0.0.0

# 或托管平台（会自动注入 PORT）
```

- **HTTPS/WSS**：如果前面有 nginx/Caddy 反向代理，转发时带上真实 IP 即可：
  `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`
- 之后所有人只需要记住这一个域名，例如 `https://drop.example.com`。

### 为什么这是根本解法

之前"换一个局域网就进不去"的原因是：信令服务器跑在某台电脑上，离开那个网络就访问不到它。现在分组逻辑在服务器端、按连接来源 IP 划分房间 —— **服务器在哪都能被访问，而"谁和谁一个房间"由各自的出口 IP 自动决定**。这正是 Snapdrop/LocalSend 类产品采用的模式。


## 进阶

- **手动指定房间**：地址加 `?room=xxx` 可覆盖服务器自动分组，只有相同 room 的设备能互相看到。
  例：`http://landrop.local:8000/?room=team1`（临时想和另一网络的人传文件时有用）
- **强制中转**（排查用）：`?forcerelay=1` 跳过点对点，直接走服务器中转
- **纯静态兜底**：页面若部署在无 Node 的静态托管上，会自动切换到公共 MQTT 信令（仅点对点，可用 `?broker=wss://...` 自建覆盖）
- **换端口**：`node server.js 9000`，页面上的二维码和提示会自动跟着变

## FAQ

**Q：点了发送，提示「连接超时／对方未响应」怎么办？**
现在不会卡死了 —— 8 秒后会自动降级为服务器中转继续传。如果连中转也失败，检查两台设备是否在同一 Wi-Fi、电脑防火墙是否放行了该端口。

**Q：为什么点对点会失败？**
多数是路由器开启了 **AP 隔离（客户端隔离）**，或两台设备不在同一子网，导致 UDP 直连被丢弃。此时会自动走中转，速度略慢但一定能成功。

**Q：`.local` 地址打不开？**
Android 浏览器对 mDNS 支持不稳定，用「📷 扫码」即可（最通用）。iOS/macOS 正常。

**Q：能用在不同网络（不在同一 Wi-Fi）的两台设备间传吗？**
分两种情况：
- **同一局域网互传（主场景）**：服务器部署在公网后，任意网络打开同一网址，服务器按出口 IP 自动让同局域网的人互见，其他人不可见。
- **跨网络互传**：双方在地址后加相同的 `?room=xxx` 即可进入同一房间；文件默认仍走点对点直传（跨公网也能直连），不通则经服务器中转。

## 项目结构

```
lan-drop/
├── server.js           # Node 服务：静态托管 + WebSocket 信令 + mDNS 广播 + 二维码
├── package.json
└── public/
    └── index.html      # 单页前端（无框架，响应式，手机/电脑自适应）
```

依赖仅 `ws`（WebSocket 服务）和 `qrcode`（二维码生成），无前端框架、无构建步骤。
